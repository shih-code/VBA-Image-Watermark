# 專案規格書（Excel 驅動型圖片兩階段批次浮水印處理系統）


**版本沿革**：V0（單一 `Mod_ActionExecutor` 上帝物件雛形）→ V2~V7（同一架構下的功能疊代，逐漸累積「變數一物多用」技術債，見 ADR-003）→ **V8「切除危機」（SRP 大重構分水嶺）** → V9~V11（管線解耦深化）→ V12（架構定案版）→ **V13（最終定案版：模組識別資訊收斂、ICommand 撤除、位置保留與空白頁面清理修復，ADR-008 至 ADR-014，全模組 VERSION 統一 1.0.0）** → V14~V17（**匯出重複檔案根治重構**：廢除日期跳號機制、改採固定工作資料夾拓撲＋事件式整批備份、Staging 新增「已匯出狀態」欄位取代脆弱的檔案存在性判斷、新增帳本與硬碟狀態一致性防呆，ADR-017、ADR-018，`Mod_WorkflowManager`／`Mod_FileSystem`／`Mod_InteractionAdapter`／`Mod_ExportPipeline` 降級為 Experimental 待實測晉升）。

**分支參考**：`V1_CL` 為 V0 之後另闢的獨立測試分支（使用另一 AI 協作、僅開發至上帝物件拆分前即未再繼續），其
`Mod_EnvironmentSetup` 對畫布位置保留問題的修復經驗，於 ADR-011 被回頭借鑑修復進 V13 主線。

## Behaviors（核心行為）

1. **匯入清洗**（`Mod_ImportPipeline.ExecuteImportPipeline`）：接受資料夾或手選檔案 → 跨批次雜湊去重（ADR-007）→ 檔名清洗防禦 → 同名跳號防撞複製 → 累積為 `cls_ImportResult` 集合 → 交由 `Mod_InteractionAdapter.WriteImportResults` 一次寫入 Staging_Images（V13 起管線本身對網格 100% 無知，見 ADR-016）。
2. **座標換算**（`View_CanvasManager.GetWatermarkPercentages`）：讀取 ConfigSheet 畫布與錨點控制項相對位置，含四向磁吸邊界防禦，換算為 0.0~1.0 相對百分比。
3. **標籤化範本排版**（`Mod_ImageWatermark.PrepareWatermarkText`）：支援 `{name}`/`{date}`/`{remark}` 標籤替換，使用者可在備註欄直接輸入含大括號的自訂範本，系統會自動辨識並整段當作範本使用（非疊加）。
4. **批次壓印匯出**（`Mod_ExportPipeline.ExecuteExportPipeline` + `Mod_ImageWatermark.ExecuteWatermarkStream`）：WIA 等比例降維（>2200px 觸發）→ Chart 動態排版壓印（依文字行數與最長字元數動態撐開底板尺寸）→ 暫存檔＋改名防半成品 → 撞名版本化退位備份（ADR-006）→ 寫入 LOG_Export_成果。
5. **斷點續跑**（V14 重構，見 ADR-017）：固定拓撲「作業資料夾／成果」，內容永久累積不清空 + 檔案存在性判斷。偵測到殘留時詢問「跳過續跑」或「結束並重印」；選擇後者時，成果整批備份進「備份／斷點備份_時間戳」（`Mod_FileSystem.BackupAndClearFolder`）後清空，並呼叫 `Mod_InteractionAdapter.ResetAllExportedFlags` 重置 Staging 表全部「已匯出」狀態，讓下一次打包重新納入全部照片。Staging 表「已匯出」欄位（第 9 欄）為 `PackageStagingTasks` 打包時的主要過濾依據，檔案存在性判斷降級為輔助防線。
6. **環境自癒建置**（`Mod_SheetSchemaBuilder` + `Mod_UIRenderer`）：冪等性檢查並重建 ConfigSheet／Staging_Images 結構、按鈕面板。畫布／出血框／浮水印錨點採雙模式（`RenderUIElements(Optional forceResetLayout As Boolean = False)`）：日常匯入（`RunPhase1`）沿用既有位置，不打擾使用者版面；一鍵重整工作檯（`RunRebuildUI`）明確傳入 `True` 強制重置回預設座標，恢復原廠設定（ADR-011、ADR-012，修復經驗借鑑自 `V1_CL` 分支）。
7. **空白頁面清理**（`Mod_InteractionAdapter.PurgeBlankOrphanSheets`）：「一鍵重整工作檯」的一部分，掃描非系統表、無 `###` 保護標記、內容真正空白的工作表，經使用者確認後刪除；偵測到活頁簿結構受保護則明確中斷，不自動解鎖（ADR-013）。
8. **歷史日誌歸檔**（`Mod_LogManager.ConsolidateAllLogs`）：以 Range.Value 直注技術（不經剪貼簿）將所有 `LOG_Export_*` 分頁合併入 `LOG_Master_Archive` 總帳，舊分頁物理刪除。
9. **開新案整批備份**（`Mod_FileSystem.BackupAndClearFolder`，見 ADR-017）：Phase 1 偵測到既有進行中工作階段、使用者選擇「開新案」時，「成果」整批備份進「備份／成果備份_時間戳」，再清空「成果」；「匯入圖片」定位為純工作複製品，不具備份價值，直接清空、不進入備份流程。
10. **帳本與硬碟狀態防呆**（`Mod_InteractionAdapter.ArchiveStaleStagingToOldCatalogLog`／`ResetAllExportedFlags`，V14 新增，見 ADR-018）：偵測到 Staging 表紀錄與實體資料夾內容不一致時（手動刪除或搬移資料夾），匯入端封存幽靈紀錄至單一固定分頁「舊目錄LOG_總帳」（直注技術附加，不經剪貼簿）並清空重來；成果端重置「已匯出」狀態，讓照片自然於下次執行重新納入匯出。

## Fail-Fast Focus（防禦極限）

- 找不到 ConfigSheet／Staging_Images／畫布控制項（`Img_Canvas`／`Txt_WatermarkAnchor`）→ 立即 `Err.Raise` 中斷。
- WIA 元件（`WIA.ImageFile`）不存在於本機 → `VerifySystemWIA` 預檢失敗，中斷並提示 `ERR_WIA_NOT_FOUND`。
- MD5 運算所需的 `.NET MD5CryptoServiceProvider` 或 `ADODB.Stream` 建立失敗 → 中斷（見 ADR-002「影響」段落，此為已知環境依賴）。
- 匯出暫存 `.tmp` 檔案匯出後不存在 → 中斷並清除殘留。
- 改名操作遭遇 Error 70/75/58（檔案鎖定）→ 最多重試 3 次、每次間隔 0.1 秒（含跨日 Timer Rollover 防護），三次皆失敗才中斷。
- 活頁簿結構被鎖定保護 → 中斷 LOG 頁建立（`Mod_LogManager`）與空白頁面清理（`Mod_InteractionAdapter.PurgeBlankOrphanSheets`），皆為明確 `Err.Raise`、不自動解鎖代管（見 ADR-013、ADR-014）。
- `RunRebuildUI` 記憶的使用者原始所在工作表（`wsCurrent`）於流程中途被 `PurgeBlankOrphanSheets` 刪除 → 容錯退回顯示 `ConfigSheet`，不中斷整支程序（ADR-014）。
- Staging 看板不符合標準 9 欄合約（V14 起，見 ADR-017） → 中斷匯出並拋出 `ERR_CONTRACT_VIOLATION`。
- Staging 表已匯出紀錄筆數 > 0，但「成果」資料夾實體檔案數為 0（V14 新增，見 ADR-018）→ 非中斷性防呆，非 `Err.Raise`，而是主動修復（重置全部「已匯出」旗標）後繼續執行，不打斷使用者流程。
- Staging 表匯入紀錄筆數 > 0，但「匯入圖片」資料夾實體檔案數為 0（V14 新增，見 ADR-018）→ 非中斷性防呆，封存幽靈紀錄至「舊目錄LOG_總帳」並清空 Staging 表後繼續執行。

## 架構流向宣告（依第四章）

本專案為多檔案 VBA 專案（V17 現況，模組拓撲架構承襲自 V13 定案版，共 19 支有效模組，模組本身未增減，僅部分模組內部函式異動，見 ADR-017、ADR-018），四層拓撲如下，完整依賴關係見
`ACDS_DependencyGraph.md`：

| ACDS 分層 | 對應模組 |
|---|---|
| Controller（按鈕接收層） | `Mod_MainCoordinator`（唯一 OnAction 入口，五個一行委派） |
| Controller（流程大腦層） | `Mod_WorkflowManager`（見 ADR-004）、`cls_DAGEngine`（生命週期守衛，見 ADR-001） |
| Service（管線層） | `Mod_ImportPipeline`、`Mod_ExportPipeline` |
| Service（專業算力引擎層） | `Mod_FileSystem`、`Mod_Crypto`、`Mod_ImageWatermark`、`Mod_SheetSchemaBuilder`、`Mod_UIRenderer`、`Mod_LogManager`、`View_CanvasManager` |
| View／Adapter | `Mod_InteractionAdapter`（全專案唯一網格讀寫與 Windows 對話框實體）、`Mod_UI_Messenger`（唯一 MsgBox 出口） |
| Database | Excel 工作表資料區（ConfigSheet／Staging_Images／LOG_Export_成果／LOG_Master_Archive）+ 實體檔案系統 |
| 基礎模型／SSOT | `Mod_StringConstants`、`cls_Settings`、`cls_ImageEntity`、`cls_ImportResult`、`cls_EventStore` |

**已知未完全解耦之處**：無。原記載於此的 `Mod_ImportPipeline` 網格耦合技術債，已於 ADR-016 修復——
新增 `cls_ImportResult` 對稱模型與 `Mod_InteractionAdapter.LoadExistingHashSet`／`WriteImportResults`
兩支函式，現與 `Mod_ExportPipeline` 對稱達成對 Excel 網格 100% 無知。

## 是否套用 Interface First（第二章第九條）

**否（Accepted，V13 定案，見 ADR-009）**。`ICommand.cls` 自 V2 起即存在，定義
`Public Sub Execute(ByVal target As Object)` 標準接口，但橫跨 V2 至 V13 共 11 個
子版本，全專案從未出現任何 `cmd*` 具體類別 `Implements ICommand`。依 AVS v1.1
第五節判準（「功能之間是否需要動態組合、彼此獨立替換、或依賴關係需要排程」），
本專案四個功能（匯入／匯出／重整工作檯／日誌歸檔）皆為固定線性流程，不滿足套用
Command Pattern 的判準；即便補齊實作，也只是在既有管線外多包一層轉發殼，不會
新增任何行為，屬規格過度。V13 正式撤除 `ICommand.cls`，本專案不套用 Interface
First 原則於此處，維持現有管線模組直接依賴具體實作的做法。
